# conflux-subscribe（订阅镜像）

Conflux 扩展订阅发布中心。两个订阅地址：

| 订阅 | 地址 | 内容 |
|---|---|---|
| 自制扩展 | `catalog.json` | 黄果短剧、瓜子影视（本仓库托管包体） |
| **官方全集镜像** | **`catalog-mirror.json`** | ConfluxOne/ExtensionSamples 全部 8 个扩展，包体直连官方 raw |

线上：`https://maxbo718.github.io/conflux-subscribe/<文件名>`

## 官方镜像会自动更新吗？

**是，全自动。** 关键点：App 只在「订阅目录里的版本号 > 已安装版本」时才显示「更新」按钮，
所以镜像不能只是一层层转发官方文件——**必须自己抓包、解析版本号、写进目录**。
这件事由 GitHub Actions 定时完成：

`.github/workflows/mirror.yml`
- 每天 3 次（UTC 02:15 / 10:15 / 18:15 = 北京时间 10:15 / 18:15 / 次日 02:15）
- 拉官方仓库全量文件树 → 对每个含 `definePackage` 的 `.js` 在 Node vm 里解析元数据
- 同一包 id 出现多次时取版本号最高的（官方 `others/` 与根目录有重复）
- 有变化才提交（`git diff --quiet` 判断），无变化不留空提交
- 也可在 Actions 页面点 `workflow_dispatch` 立即跑

自动发现新扩展：官方新增 `.js` 文件会被自动收进，不需要改代码。

## 手动发布自制扩展

```bash
sh publish.sh          # 构建 + 推送 + 轮询线上确认生效
```

构建自动扫描 `../conflux-*.js`，排除：
- 带点号的备份名（`conflux-guazi.v105.bak.js`、`.v130.optional.js`）
- 包 id 以 `.probe/.test/.debug/.bak` 结尾的临时包
- `subscribe-meta.json` 里 `_exclude` 列出的

**每次改动必须升版本号**，否则 App 收不到更新。

## 已知坑（都踩过）

1. **App 订阅行为**：启动时若某订阅超一天未刷新，后台自动下载并安装**新出现的包**；
   但**已装包不会自动更新**，必须在订阅详情里手动点「更新」。所以「不用反复导入」成立，
   但「彻底不用点」不成立——点一次更新即可。
2. **版本号格式**：只认 `主.次.修订` 纯数字；`1.3.0-beta.1` 与 `1.3.0` 视为同版本。
3. **目录版本低于实际版本**时，用户会看到「安装较旧版本」按钮，所以镜像必须真的读到官方最新版。
4. `packages/` 下的文件名必须带 `.js`，否则 App 404。
5. 远端残留清理要按带扩展名的文件名比对，否则会误删正常包。
